# 驾驶与装卸全流程

从工作台的地图路线行点击“驾驶全程”，或在“三维装卸”点击“驾驶与装卸全程”。页面绑定当前批次、仓库、车辆与方案版本，默认暂停在仓库驾驶室。

## 演示内容

同一条时间轴串联：空车准备、仓库逐箱装车、道路行驶、到店停车、冷链取货、临时倒货、逐箱卸货、回收装车、驶往下一门店与返仓交接。三店示例共有44个原始装卸状态，按实际路线顺序插入驾驶与停车后共53个阶段。

为完整表现第一箱装车，画面使用本地克隆的空车准备状态，再播放第一箱从尾门进入。这个准备状态不改写后端原始44帧，原始帧保持完整、按顺序各出现一次。返仓时回收物和共享箱仍留在车上，停在交接前，没有擅自变成已卸空或已签收。

驾驶室、跟车、路线全景和货物近景可以切换。“跟随流程”会在行驶阶段显示驾驶视角，到店后自动切换装卸。支持暂停、倍速、进度拖动、上一步、下一步、门店跳转和重播。

## 数据和状态

`GET /api/multiwarehouse/journey` 在同一任务快照中取路线、道路矩阵、车辆和箱位，带旧方案编号时拒绝读取。每一腿连接原方案相邻门店，包含最后返仓，不把道路展示几何写回计费里程。

道路模型包含驾驶室、厢车、建筑窗、店招、仓库装卸口、树木、路灯、车道及斑马线。转弯采用道路范围内的平滑路径，车辆与相机共用右侧车道偏移。播放进度不冒充实际车速或配送时长。

整个页面只读取方案和推进画面，不写入签收、回收、温度或调度事实。只有出发装载、没有完整装车及返仓步骤的旧模型，不开放完整流程演示。缺数据、旧版本和WebGL失败都有明确恢复入口。页面退出时释放两个渲染器，后退缓存恢复时重新载入。

## 验证

本轮全量404项测试通过，记录见 `outputs/journey-qa/final-tests.txt`。专项命令：

```powershell
python -X utf8 -m unittest discover -s tests -p test_journey.py
node scripts/verify_driving3d.cjs
node scripts/verify_journey_flow.cjs
```

驾驶专项核对路线端点、弧长进度、转弯、相机右方向及1001个道路采样。流程专项核对空车准备、原帧完整性、全阶段自动视角、跳转、暂停与重播、返仓带回物，以及渲染器失败和页面退出时的资源释放。

浏览器按桌面与390像素手机检查驾驶室、逐箱装车、到店停车、冷链取货、回收与返仓，并走完整条自动播放。截图保存在 `outputs/journey-qa/`。

页面已删除重复的底部说明句，参数和数据范围保留在输入及项目说明中。自动样式检查使用简化解析，未据此声称完成计算对比度检查；颜色、标签和手机布局另按实际画面复核。
