# 完整约束下的小规模搜索诊断

2026-11-05。本轮完成算法诊断、显式多布局试验接口、失败触发策略和离线对照。默认工作台仍使用原构造；没有改企业资料、数据库、费用口径或对外派单。

## 已得到的结论

1. **确实存在装载构造遗漏。** 一个明确的三箱反例中，旧装载顺序找不到位置，改变同面积箱子的先后顺序后，同车、同路线、同箱规和固定朝向下可以装入并卸出，独立动作重放通过。
2. **没有证据支持无条件替换默认求解器。** 8个预定义业务机制变体中，现行算法得到6个完整方案；在旧装载构造下枚举所有分车和站序，6个方案已达到相同排名。多布局在固定在用车辆、逐车重量/体积利用率降幅不超过2个百分点、名义费用不增的护栏下没有找到更优方案。
3. **不同用车方案需要单列。** 紧冷链35分钟的构造案例中，旧构造找到4个完整方案，最好325元、2车；多布局找到12个，最好185元、1车，但增加搬倒并延后最后返仓。它不满足固定在用车队的主对照口径，不能称固定车队降本，也不是实际企业节省。
4. **按需触发比无条件尝试更值得继续，但只在失败时触发还不够。** 前9个案例中，失败触发保留6策略全尝试的完整方案找到数及最好排名，减少放置检查；补充高装载案例中，它错过了一个已可行方案的搬倒改进。所有策略均失败时仍可能支付完整开销，不承诺与旧构造同成本。

## 改动及使用范围

`operational_constraints.py` 新增：

- `evaluate_route(..., packing_variant='legacy')`：默认策略不变；显式允许改变装载排序或候选位置遍历顺序。
- `search_route_layouts(..., max_variants=6)`：保留旧候选，最多尝试6种确定性布局策略。
- `stop_on_first_feasible=True`：旧布局通过即停止；失败后才逐个尝试其他策略，找到通过布局即停止。

各策略仍执行同一套几何、支撑、承重、尾门通路、临时地面区、共享冷链箱、设备时限、回收与装卸时间检查，并做独立动作重放。不旋转箱体，不增大容量，不改变硬约束。

策略间共享8192次路线放置检查预算，覆盖出发装载、临时区、恢复和回收。约束校验阶段的冷箱内部构造另有既有预算，不计入此数；耗时计入调用总耗时。预算耗尽且尚无通过方案时返回 `SEARCH_BUDGET_EXHAUSTED`；已有通过布局则保留，并在 `layout_search.budget_exhausted` 中标记后续搜索中止。

实验接口返回实际箱位、动作和所选策略。必须保存所选报告；仅保存站序再用默认构造重建，是另一次构造，不能冒充对该布局的复核。因此本轮没有把接口直接接入方案确认和三维显示。

## 反例

构造可用空间60×50×10厘米，同店三箱：A=50×30×10、B=10×40×10、C=40×10×10厘米。低矮空间用于边界诊断，不是实际车辆尺寸。

- 旧顺序A、B、C：B先装入后阻挡C的入车通路，返回 `packing_not_found`。
- 同面积按宽度升序后A、C、B：全程通过，10个记录状态，0次倒货。

没有使用旋转、拆单、增加车辆或放宽路径约束。这是搜索遗漏的机制证据，不是独立业务收益样本。完整输入见 [反例证据](../outputs/search-diagnosis/packing_counterexamples.json)。

## 路线枚举对照

脚本预定义共享箱常规、冷链50/35分钟、紧时间窗、高回收、禁倒货、紧凑空间、紧班次8个业务机制变体，再加入上述装载顺序反例。它们来自少量构造母例，不是9个独立企业批次，不能据此推断总体成功率或统计显著性。

每种模式遍历122种合法整店分车与站序，包含共享箱整组分车。比较三种有限构造：legacy、portfolio（6策略）、fallback（首个可行即停止）。所有路线遍历均完成，预设案例未触发布局预算或实体上限。

本次实际唯一候选的工作量，包括被拒候选、空车试次；缓存命中不重复计数：

- legacy：15499次放置检查、146个布局试次，枚举与核验合计约4.51秒。
- portfolio：100888次检查、900个试次，约32.34秒。
- fallback：57054次检查、436个试次，约18.29秒。

这些时间是本机离线遍历与核验总耗时，不是同规模单次排车时间，更不是人工调度耗时。墙钟结果可能随机器负载变化；检查次数更适合复核工作量。

禁倒货与紧凑空间两个案例均未找到完整方案，失败保留，不解释为已证明物理无解。反例在legacy下没有完整方案，多布局与失败触发均找到2个（分别使用同一可用车队中的一辆），不拿部分旧方案计算费用节省。

排名沿用完整模型的迟到、费用、高风险搬倒、总搬倒、返仓时间之和及里程。时效取专项 `adjusted_route`，基础 `plan.metrics` 保留原核算合同，不能直接当成含装卸后的指标。

完整记录含原始构造输入、指纹、最佳候选实际箱位与动作、独立核验、失败原因、搜索工作量和预算计数：[完整路线诊断JSON](../outputs/search-diagnosis/operational-search.json)。

## 证明边界

本轮对分车与站序充分枚举，**没有对所有几何位置、装载顺序及动作序列充分枚举**；因此只是选定有限构造下的路线参考，不是联合问题的全局最优证书。`enumeration_complete` 仅表示路线遍历完成，布局及实体预算另列。

原8个业务机制案例出发装载压力较低，不能据此证明接近人工90%装载时的表现；补充高装载实验单独列在下节。模型中的固定朝向、全底面单箱支撑、每店回收包装合成堆叠/套叠实体属于明确建模边界。更改这些规则必须另设对照，不能混进同规则算法收益。

没有真实订单、人工同批计划、真实装卸工时、GPS/TMS计费里程或温度设备接入，本轮不是现场履约或经济收益证据。

## 补充：90%装载压力诊断

为避免只在低装载样例上讨论改进，另预定义4案：常温无回收、常温有回收、共享箱无回收、共享箱有回收。全部保留，无按结果剔除。它们仍来自同一构造母例，不是独立验证集或真实企业批次。

空间统一为300×80×30厘米、可用容积0.72立方米，仅作形状及装载压力测试，不是实际4.2米车厢。常温9个标准箱出发0.648立方米、63千克，载重上限70千克；共享箱案例为8个标准箱加共享箱外壳，出发0.648立方米、67千克，载重上限67/0.9千克。带回收案例每店2纸箱、2周转箱，套叠高度30厘米。共享箱内尺寸40×25×20厘米，外尺寸60×40×30厘米，自重和顶部承重限制保持明确。

每案分别枚举全部合法分车及站序，常温各24种、共享箱各12种，每模式合计72种。现行算法和三种参考模式全部找到完整单车方案；实际分配车辆的出发重量和外占体积利用率均为90%，费用185元。布局及实体预算限制计数均为0。

**常温90%＋回收出现一个严格护栏内改善：** 同一车辆、同一站序、同一25公里路线、双维90%装载、185元费用不变，`wide_lanes`布局将倒货18次减至16次，模型额外作业时间6.66→5.96分钟，最后返仓573.66→572.96分钟。独立动作重放通过。0.7分钟来自声明的每次搬倒0.35分钟，不是现场实测节省；倒货次数是移出/恢复动作数，不等同于受影响货物件数或货损率。

另外3案未发现多布局的排名改善。失败触发策略因旧布局已通过，不会搜索这个已可行方案的改善，常温回收案仍是18次。因此后续可以研究高搬倒或紧时限时触发，但触发阈值必须在新预设案例上检验，不能用本案反向调阈值后宣称独立有效。

本机最终复跑各案完整枚举耗时范围：legacy约0.25—1.13秒、portfolio约1.91—5.98秒、fallback约0.43—1.36秒；不是单次生产求解性能。完整输入、各车真实装载率及最佳动作见证见 [高装载诊断JSON](../outputs/search-diagnosis/high-load-search.json)。
