# 本地交接包与云载字段合同

2026-11-01。本文描述已实现的 `logireflow.local-handoff.v1` 本地只读 JSON 合同，不是传化云载的官方接口规范。当前未取得本项目实例、鉴权、订单与结果回传接口或接收方确认，不能称为已经接入云载或已经派单。

## 已实现的本地入口

`integration_contract.export_handoff(task)` 根据一个已保存应用任务生成字典，不修改任务、不调用网络、不执行真实发送。`integration_contract.validate_handoff(package)` 对版本、单位、来源、预测与记录的语义、门店完整性和确定性内容指纹做检查；通过返回 `passed=True`，失败抛出 `ValueError`。

页面导出由应用服务提供，导出前仍检查当前任务修订。未确认或已过期任务可以导出用于核对，但会明确保留阻断原因，不生成可冒充当前方案的剩余预测。原出发前计划、当前剩余预测、签收回执和位置/等待观察分别保存，不能相互代替。

## 字段与解释

| 字段 | 本地含义 | 证据与使用限制 |
|---|---|---|
| `schema_version` | `logireflow.local-handoff.v1` | 本地合同版本，不是企业API版本 |
| `handoff_id` | 对除自身外的规范化JSON内容计算SHA256 | 同一快照重复导出相同；任务修订、观察时刻、已采用版本或导出业务内容变化后改变 |
| `task_ref` | 本机任务ID/修订、输入修订与哈希、原方案ID、当前剩余采用版本和保存时间 | 本机身份用于追溯，不是企业订单或车次编号 |
| `source` | 构造输入或企业来源声明、道路说明、箱规估算依据 | `enterprise` 只是来源声明，仍为 `enterprise_source_claim_unverified` |
| `enterprise_mapping` | 原始本机ID与尚待确认的企业映射占位 | 所有企业ID为 `null`、状态 `pending`；配送日期和任务时区也为待确认空值 |
| `original_plan` | 已确认原方案的出发前顺序、预计时间、载荷、道路估算与费用 | `departure_prediction`；费用是出发前估算，不是改序后重新结算或实付金额 |
| `current_remaining_forecast` | 当前未签收门店顺序、预计时间/载荷、回仓、风险和计算锚点 | `remaining_prediction`；保留原车归属；已签收店不得重新进入剩余列表 |
| `recorded_facts.receipts` | 本机追加的整单签收/回收和回仓记录 | 模拟演练标为 `synthetic_record`；人工录入标为 `manually_reported_unverified`，不等于电子签收证明 |
| `recorded_facts.observations` | 已知节点位置和原地等待观察 | 不代表GPS定位或签收，不改变货物和已收包装；位置/时刻/来源与预测锚点互相引用 |
| `units` | kg、m³、km、CNY、包装只数、当日分钟与UTC保存时间 | 道路估算km、TMS合同计费km和实际GPS公里不能混用 |
| `readiness` | 本地核验状态与外部阻断原因 | 本地核验通过仍不表示可派发或已接入 |
| `dispatch_status` | 固定 `not_sent` | 不能改成 `sent`，不生成接收方回执 |
| `integration_status` | 固定 `not_connected` | 不能改成 `connected` |

当日分钟是任务当天00:00后的分钟数，可以包含预测计算的小数；保存时间使用UTC ISO8601。这两类时间不能直接相互替换。现有任务尚无独立配送日期和任务时区字段，不能把客户端当天日期或UTC记录日期擅自当成配送日期，联调前必须明确。

导出通过字段白名单组织结构化业务结果，不复制整个任务字典、原始上传文件、密钥、自由备注、模型会话或完整求解历史。人工来源备注仍保留在本机记录中，本合同只导出其来源类别与记录身份；若企业要求来源单据字段，需另行确定字段及数据使用范围。

## 核验与阻断

`readiness.status` 当前始终为 `blocked`。企业映射、配送日期/时区、真实目标实例和接收结果未确认是明确阻断条件，即使本机原方案及当前剩余路线通过核验，也不能将这个包直接当成真实派发许可。

`local_plan_status` 区分未确认、旧输入方案、部分未安排、本地约束风险以及当前已确认。导出时会重新调用原方案独立核验和同车剩余核验；当前超容或收货截止等风险保留在包中供核对，不删除实际已报告回收量。

包校验还检查：已签收与未签收集合不相交；每车剩余门店与该车原方案减去已签收后的集合完全一致，不能漏单、重复或换车；已签收数量、下一店、回仓状态和整体完成状态与记录一致；当前锚点引用本车最新有效观察或最新回执，位置/时刻/来源必须一致，不能改名为GPS来源。企业映射占位不得伪填为真实编号。

确定性ID只是在本机或人工交换文件时识别同一内容的依据。SHA256是公开可计算的，任何有内容的人都可以重新计算，因此它不是数字签名、身份认证、篡改来源证明或远端幂等保证。校验通过也不证明人工记录真实，更不证明现场装卸或道路可达。真实接入需要接收方合同、鉴权、幂等键、接收状态及失败/超时语义。

## 真实联调前必须确认的映射

| 当前本地对象 | 待企业确认内容 |
|---|---|
| 本机任务ID | 企业实例、租户/权限范围、批次/运输任务编号、配送日期和时区 |
| `depot_id` | 仓库业务ID、实际地址/坐标、适用区域与波次 |
| 每个 `stop_id` | 企业门店ID与该次访问的原始订单ID列表；同名不得自动合并 |
| 本机车辆ID | 企业车辆/承运商/司机/车次ID与可用时段；不能凭本机TRUCK编号回传 |
| cartons / totes | 企业包装类型ID、压平/套叠口径、数量/实收/差异字段和单位 |
| 原方案/剩余版本 | 企业接受“更新计划”还是“新运输任务”，如何保留已签收事实 |
| 道路估算与费用 | 合同计费公里、实际公里、门店服务计次、分段费率、结算责任方 |
| 签收/位置/等待记录 | 原系统回执编号、事件类型、发生时间、接收时间、证据来源和更正机制 |
| `handoff_id` | 接收方是否接受此ID作请求关联字段；真正防重派发须由接收方验证 |

还需取得本项目测试环境、具体读写接口和请求/响应样例、认证与权限边界、错误码、重复提交、超时待核查、回传失败恢复及接收方可核对的记录。公开产品页或API分类不是本项目接口已经可用的证据。当前模块没有配置接口地址、申请令牌或外发数据。

## 验证与复现

运行 `python -X utf8 -m unittest discover -s tests -p test_integration_contract.py -q`。当前10项测试覆盖：重复导出确定性和只读、未确认/旧输入阻断、本地确认不冒充企业接入、签收与观察分列且锚点一致、观察时刻变化导致ID变化、重新计算哈希后仍拒绝漏单/假下一店/伪企业映射、超容事实保留、自由备注与非合同字段不外带。

运行 `python -X utf8 scripts/reproduce_handoff.py`，在独立 `outputs/handoff-reproduction/tasks.sqlite3` 创建构造任务、确认原方案、记录等待观察，保存 `outputs/handoff-reproduction/handoff.json` 并验证可重复导出。复现不联网、不调用模型、不连接企业系统、不发送派单。
