# 同页交互调度状态合同

2026-10-12。本轮是原能力的状态整合，不是新路线/装载算法，也未证明原创性或企业收益。入口为scenario.html#interactive；上半部脚本回放和下半部交互场景独立，不能把脚本签收当交互事实。

## 已完成

同批五份输入创建出发状态，选择fixed或csv模式。fixed调用原联合求解、冻结箱规/车厢/坐标和独立核验；csv复用原仅重量/体积的连续模型，不将上方3D结果移植到该场景。模式仅在出发时选择，事件接口不接受模式切换。

交互依次为：消息理解与补问（可选真实AI调用）或人工填字段→服务端校验→人工核对事件→生成候选→核对漏单/路线/费用/固定摆放→单独采用→人工模拟到达/卸货/签收。AI理解不保存候选、不采用、不派单。无密钥手工填写仍可运行，不能称为AI理解。

所有修改带场景id和revision；采用和放弃还带candidate。生成候选和采用分别要求reviewed=true，前者重新校验原始草稿，不信任客户端计算的事件。执行进度变化使旧候选失效。AI调用期间场景变化则拒绝理解结果，补问最多保留4条用户原话；这是现有提取器的限制。

刷新按场景id取当前状态，允许旧revision用于恢复显示；刷新不修改状态。失效响应禁用修改按钮，可刷新或清除失效页面重开。后端仍逐次检查修订号，不依赖前端按钮禁用保证正确性。

fixed只读几何由服务端fixed_loading.check根据当前货物/签收历史重放原坐标；到达、卸货中、生成候选及采用均不重摆。签收释放整单箱体，同页3D只移除这些箱体，保留剩余坐标。图、当前执行与候选分开，候选未采用不替换当前布局。csv隐藏交互3D，并明确未核验几何。

csv最多两批紧急新货，每批独立仓库取货编号和8分钟构造装货时长。交接显示货物归属、取货任务、预测与已记录回执；推进时钟会按原模拟模型完成取货，这不是仓库真实回执。fixed继续拒绝新货，不能只凭重量/体积把货放进原装载。

## 存储与输入

新增scenario_workspace.py为每次开始创建独立系统临时目录和DispatchStore，复用continuous.py而不写data/sessions.sqlite3。最多12个并存场景；闲置超过两小时在下一次请求清理，服务重启失效；同一页刷新后需重新开始，状态可先导出JSON留档，暂不支持导入恢复。结束按钮清理当前临时场景。已有历史与原详细工作台不迁移、不覆盖。

POST入口为/api/scenario/live/start、action、draft、interpret。start包含input={csv_files,loading_profile}和mode；action含id/revision/action及对应业务字段；draft/interpret分别含草稿或message/context。启动最多4MB，其余16KB；不接受非有限数字。这里是本地演示接口，尚不是企业接口、账户权限或生产持久化合同。

导出包括当前已采用状态、候选历史、人工模拟回执、只读交接与固定几何。输入真实性、真实GPS/道路时间、业务资质、温控及企业成本规则均需额外数据与授权验证。

## 尚未实现

固定空间中新货插入与装货过程、故障转货、更多紧急单、新地址/拆单、企业TMS/WMS/GPS/司机接口、生产登录与持久化。不能将“同一入口有两个模式”说成“固定装载与紧急新货已联合完成”。下一步仍需先定义原箱体不动、新箱体进入剩余空间、回仓取货事实及候选采用时的坐标增量合同，再用反例验证。
