# 冷链、沿途空间与三维装卸

2026-11-05。双击项目根目录的“打开城配续航.cmd”，在工作台展开“示例任务”，选择“冷链与回收示例”，点击“保存并计算”。“方案核对”查看路线和约束，“三维装卸”查看车厢与逐站动作。现有界面风格保留。

## 算法接入情况

每个仓库独立保存 `operational_policy`，没有模块级全局规则。修改参数会使旧候选失效；确认前重新核验。旧任务没有专项参数时显示未配置，不按已通过处理。

| 项目 | 本轮实现 |
| --- | --- |
| 运费 | 每车次140元起步，超过100公里的部分每公里2元，每店15元；按往返里程计，不重复收装卸费 |
| 共享冷链箱 | 内外尺寸、箱体自重、商品重量、温区、开启次数、开箱工时、启用时刻与有效时长；跨店共享箱安排在同车，商品交付后箱壳仍占位直到返仓 |
| 车辆与冷链 | 独立保温箱与需要车厢制冷的设备分开；普通新能源车不自动视为冷藏车 |
| 沿途空间 | 配送卸货、回收纸箱压平、周转箱套叠、密封常温退货逐站更新箱位和载荷 |
| 装卸可达性 | 尾门通路、箱体重叠、车厢边界、完整底面支撑、顶部承重、易碎及不相容货物；受阻时检查临时倒货区并恢复货物 |
| 时间与能量 | 倒货、回收、开箱工时计入到离店与返仓时间；检查准备完成时间、声明能耗与电量余量 |
| 独立核验 | 对中间箱位和动作重放，核对重量、尺寸与货物变化；超预算返回搜索中止，不称物理无解 |

构造预算为160个实体、8192次候选放置检查、512帧。求解、人工调整、确认、Agent建议和三维查看共用专项核验。配送清单使用计入装卸耗时的到离店时间。

## 三个可展示的视角

同一输入、同一规则独立复查，完整输入和结果保存在 [三组对照证据](../evidence/operational-comparison-20261105.json)。

1. **货送完，不等于箱子腾空。** 原商品体积规则允许的路线，在保留共享箱外壳后可能放不下回收物。重点是配送与回收共用整段路线空间。
2. **总体积够，不等于形状能装入。** 特意设置20厘米高的边界测试空间，保持朝上的25厘米周转箱无法装入，尽管总体积检查通过。这是反例测试，不是实际车型尺寸。
3. **最短路未必满足冷链时限。** 三店六种顺序中，25公里的最短路违反声明的设备有效时限，26公里路线可以通过，两者运费均185元。有效时长35、45、50、60、90、180分钟时，可行顺序分别为0、2、2、4、6、6种。

默认示例能以1车完成3店。候选27公里、185元；相较25公里基线，倒货动作从12次减至8次，额外作业时间从11.1分钟减至9.7分钟，但返仓时间略晚。这是距离、作业和冷链的取舍，不能说所有指标都更优。

## Agent与执行

助手增加约束检查和车厢查看，回答关联当前批次、仓库、车辆及候选版本。回收压力试算逐店增加周转箱并完整重放冷链与空间规则；不再绕过专项约束走旧求解器。不可比的基线不会被当成降本依据。

执行记录保留共享箱壳、自重及实际回收偏差。三维画面仍表示方案中的箱位，实际温度和现场箱位需要观察数据。有专项规则且已有执行事实的批次暂不开放剩余改序，避免用原始箱位覆盖现场状态。人工确认和企业派单仍分开。

## 三维与页面

Three.js模型包含车厢、驾驶室、车轮、底盘、尾板、箱体、共享冷链箱和临时倒货区。箱位、尺寸及动作来自算法结果；没有坐标时不生成替代货物。支持整体、尾门、俯视、侧面、剖切、分解、点选与44帧示例播放；动画经过尾门和临时地面区。

页面文案按工作台、助手、三维及静态页面分工检查，收短提示，合并重复声明。门店、车辆和仓库使用顺序标签，内部编号保留用于关联记录。

## 参数与验证范围

示例按4.2米新能源厢车量级设置可用空间420×210×210厘米，独立共享保温箱声明温区2—8℃。尺寸、180分钟有效时长、开启次数及工时均为可修改建模参数，来源和假设随输入保存。

未覆盖实测温度变化、冷链商品退货、箱内逐件取货路径、轮包与轴荷、制动和人员安全、自动充电排程及跨批次车辆占用；没有接入企业TMS、GPS或温度设备。

全量391项测试通过，记录见 `outputs/operational-qa/final-tests.txt`。另检查桌面与390像素手机布局、实际WebGL加载、逐帧切换、多角度、分解与播放。未调用付费模型接口，未改企业数据。
