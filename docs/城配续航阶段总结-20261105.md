# 城配续航阶段总结

我们围绕传化给出的医药城配场景，把配车、送货顺序、车内摆放、包装回收和费用放在同一批任务里处理。调度员能够查看方案、调整路线、核对约束，确认后记录签收、回收与温度异常。地图和车厢画面使用当前方案的数据，帮助人看清算法为什么这样安排。

## 作品现在解决什么问题

这类配送的难点贯穿整条路线。出仓时货物能装下，到了门店，还要取出指定货物、带回空箱或退货。共享冷链箱里的商品逐店交付，但箱壳仍留在车上。门店收货时间、保温时限、倒货工时和回收空间会相互影响，单独优化某一项很容易得到现场难以执行的方案。

我们的处理方法是，把整店任务分给车辆，在候选路线上构造箱位和装卸动作，再按每个中间状态检查重量、空间、温区、通路与时间。没有找到合适摆放时保留原因，调度员可以调整参数或生成新的人工候选。参数按仓库保存，修改后原候选失效，确认前重新检查。

## 三个主要亮点

### 配送和回收共同决定整条路线的载荷

回收进入每站的空间计算。纸箱压平、周转箱套叠、常温退货和共享冷链箱都有明确外形及重量。某站卸货释放了多少空间、随后回收又占用多少，都能沿途重放。

这里最值得讲的是共享箱：商品交付后，箱内货重下降，外部占位仍在。只按剩余商品体积估算，会高估后半程可用于回收的空间。我们已经用构造反例验证，这一遗漏可以改变一条路线是否可行的结论。

### 路线比较同时看时限、作业和风险

在满足硬约束的前提下，比较时效、费用、高风险搬倒、总搬倒和返仓时间。冷链与易碎货搬倒单独计数，避免仅凭距离选路。

三店对照中，25公里的最短路违反声明的保温时限，26公里路线可以通过，两者费用均为185元。这说明，多走一公里可能换来满足冷链条件的配送顺序。

另一个示例中，候选从25公里变为27公里，倒货从12次减到8次，额外作业时间从11.1分钟减到9.7分钟，但返仓略晚。这是能够解释的取舍，适合展示调度员如何按业务重点选择方案。

运费沿用已确认口径：每车次140元起步，往返超过100公里的部分每公里2元，每店15元，门店服务费包含卸货和带回包装、退货服务。

### Agent把方案、依据和可视化连起来

助手可以检查约束、解释费用与风险、提出调车或调序候选，并关联对应车辆的三维车厢。回收压力试算会重新检查冷链与沿途空间，不能绕过专项约束。方案确认、签收与处置仍由人操作。

地图使用固定门店编号，另外标注第几站，显示配送方向和返仓路线。装卸图默认货物近景，能逐步查看卸货、共享箱开箱取货、临时倒货及回收装车。点选箱体可以查看尺寸、重量、所属门店和持续占位。

本轮把驾驶主视角加入了这条流程：空车准备、仓库逐箱装车、道路行驶、到店停车、逐步装卸、前往下一店与返仓交接。支持驾驶、跟车和路线全景，也可以查看货物近景，使用统一时间轴暂停、跳转、调节播放速度。默认三店示例保留原始44个装卸状态帧，加入行驶和停车后组成53个阶段；门店顺序、箱位、共享箱剩余货重和回收物沿用同一份方案。第一箱也会从车外经过尾门进入车厢。桌面、手机与整条自动播放均已验收。

## 这几轮补齐了哪些关键问题

| 发现的问题 | 当前处理 |
| --- | --- |
| 普通货可能占用声明的冷链专用区 | 构造摆放和独立审计同时检查分区隔离 |
| 共享箱交付后可能被误当成释放全部空间 | 保留箱壳、自重和外部占位，逐店减少箱内货重 |
| 商品退货收货工时漏算 | 按件计入作业、硬时间窗及返仓时间 |
| 冷链开箱前后快照不一致 | 扣重前保存原状态，核对动作与状态变化 |
| 只看总搬倒，未区分高风险货物 | 增加冷链、易碎货搬倒次数参与路线比较 |
| 只有设备温区和时限，没有执行温度记录 | 增加装车、在途、卸货读数和追加处置，保留原异常 |
| 图像看得到车辆，看不清货物 | 默认近景、跟随动作、高亮当前箱体，增加清单与点选 |
| 标签和说明过多 | 门店、车辆、仓库使用短编号，集中保留来源说明 |

有温度记录后，原输入锁定。异常读数可以如实保存，后续正常读数不会自动清除原异常；追加处置保留与原记录的关联。温度记录不会改写车辆位置、签收进度或设备启用时刻。

## 比赛中要讲清的范围

当前工作台每仓最多12个配送任务、4辆车，最多8仓，按仓独立求解。输入先明确订单、车辆和仓库归属；同店身份需要在导入前统一。算法使用有界启发式和独立核验，不承诺全局最优或大规模分钟级性能。

企业TMS、GPS、温度设备和司机端尚未接入。地图缺坐标时采用城区场景建模，场景道路不用于正式计费。离散温度读数不等于连续温控；冷链退货、充电排程、多趟车周转、跨批次车辆占用、轴荷及车辆故障救援尚未完成。
