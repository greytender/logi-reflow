# 场景约束复核

对照资料：`docs/reference-materials/城配业务场景说明（物流服务业务）.pdf`，共8页。第1—3页是业务说明，第4—8页补充了更具体的约束、业务与技术要求。本表核对当前代码及专项测试；“已实现”表示在输入与模型范围内具备对应能力，不等于企业现场验收。

## 本轮补齐

| 原文要求 | 查出的问题 | 本轮处理 |
| --- | --- | --- |
| 第4页：冷链与非冷链分区隔离，冷链箱与制冷区域匹配 | 冷链箱会被限制在车厢温区，普通货却仍可能占用这块区域 | 车厢温区专用于冷链箱，普通货、空包装与常温退货不能占用；构造与独立几何审计同时检查 |
| 第5—7页：装车、在途、卸货温度记录，异常司机协助处理并追溯 | 只有温区、时限等设备参数，没有温度记录和后补处置 | 增加按车、按箱、按环节的温度记录和异常处置记录；异常读数能保存，后续正常读数不会自动清除异常；处置追加关联原异常，保留原值、时间和来源 |
| 第5页：高风险货品优先装卸，减少搬倒 | 按站卸货时已优先取冷链与易碎货，但路线排序只比较总搬倒 | 增加冷链、易碎货搬倒计数；同等时效与费用下优先减少高风险搬倒，再减少总搬倒 |
| 第5页：退货回收与装卸服务时间计入路线时窗 | 空包装收货有计时，商品退货逐件收货工时漏算 | 声明退货件数乘以每件收货工时，计入到店完成、硬时间窗与返仓 |
| 第8页：清楚展示装载及装卸步骤 | 开箱动作的“操作前”快照在扣重后才复制，前后重量相同 | 扣重前保存原箱体，并增加动作快照与独立状态的一致性检查，3D可以正确呈现开箱取货前后变化 |
| 第2、4页：新能源车辆补能条件 | 输入允许每公里能耗为0，可使能量检查失去意义 | 启用能量检查时，每公里能耗必须为正数 |

温度记录属于人工或示例读数。三个环节都有记录，也不代表覆盖了全程连续温度；“已记录处置”表示有处理记录，不直接判定货品可继续销售。记录不改变车辆位置、配送进度或保温设备启用时刻。

## 原文要求逐项核对

| 页码与要求 | 当前处理 | 仍需注意 |
| --- | --- | --- |
| 1：中心仓到长沙及周边门店 | 按仓库、门店与有向道路矩阵组织批次 | 地图道路与企业计费里程分开，场景地理展示不能替代TMS里程 |
| 1、2：正向配送和空箱、退货随当次回仓 | 逐站先卸后收，载荷与三维占位持续到返仓 | 商品退货目前只支持声明的封闭常温隔离箱；冷链退货未实现 |
| 1、5：多SKU、标准框与纸箱，规格统一 | 商品、冷链箱、回收箱、车厢尺寸采用同一单位，校验体积与尺寸一致 | 不推断异形货物与轮包空间 |
| 1、5、6：运费核算、往返区间与到店费 | 按用户确认口径：140元起步，100公里之外每公里2元，每店15元，含周转箱、退货、卸货服务 | 原文超100公里表格略有歧义，本项目依用户明确解释，不重复收费 |
| 1、5、7：里程以TMS为准、对账和复核 | 输入保留道路来源，费用分解与导出可复核 | 未对接TMS，不能把道路展示距离称正式结算里程；自动企业对账未完成 |
| 2、4、6：同一门店不得拆至两车 | 同一门店ID作为整店分配单元；共享冷链箱关联的门店还会成组分车 | 导入前须统一门店主数据；同名、同地址不会被自动猜成同一收货人 |
| 2、4：载重和容积上限 | 出发、每次卸货、倒货、回收与返仓中间状态逐一检查 | 载重利用率和空间利用率分别展示，不能只看其中一个 |
| 2、4、6：收货时间窗、8:30取货、当日送完 | 示例发车8:30；检查到库、装车时长与准备截止，服务、开箱、倒货、回收时间计入窗口与返仓班次 | 时间窗到达/完成口径可配置；其他场景可改班次，不应默改企业口径 |
| 4、6：冷链与非冷链分区，制冷区域匹配 | 独立保温箱与需要车厢温区的箱体区分；车厢冷链分区与普通货隔离；设备温区必须落在商品允许区间内 | 保温箱闭合外壳作为独立包装，不能以此证明实际无污染或温度合规 |
| 4：易碎怕压、层位、堆码 | 完整底面支撑、累计承重、易碎顶面不承重；逐帧复核 | 轴荷、制动稳定、捆绑与人员作业空间不在当前模型内 |
| 4：可用车辆与补能条件 | 只在已提供车辆中分配；检查往返声明能耗、电量与回仓余量 | 没有充电站排程、多趟车周转或跨批次占用日历 |
| 5：温度全过程管理和异常处置 | 参数阶段核验温区、保温启用时刻、有效时长、开箱次数；执行阶段保存读数、缺失环节、异常与处置 | 无温度传感器接入，不计算真实热力学温度变化 |
| 5：冷链、易碎优先装卸，减少转运 | 同店优先处理冷链和易碎箱；尾门受阻时明确临时移出与恢复；高风险搬倒进入路线比较 | 不是把冷链放到所有时间窗之前，仍须满足路线硬约束 |
| 5、6：无前期回收订单，回收量纳入配载 | 可输入预计空箱、周转箱与退货；实际空包装回收偏差会保留事实并提示超容 | 尚无实际商品退货件数的独立回执；退货空间按声明清单计算 |
| 5、6：门口包卸包送、签收与回收 | 按已确认路线逐站记录签收、回收和返仓，记录来源、时刻与备注 | 现阶段为本地记录，不等于门店电子签章或企业履约证明 |
| 5：每日多批次、订单采集合并与批量导入 | 批次保存、JSON导入与原始Excel核对分别实现；SKU和车辆输入校验 | 原始资料映射有缺项时不直接生成配送方案；未接企业自动采集 |
| 6、7：满载、低成本、短里程、短时长、低风险多目标 | 硬约束筛选后比较时效、费用、高风险搬倒、总搬倒、返仓和里程；规则基线可对照 | 有界启发式，不是全局最优；不以单一指标改善冒充全面改善 |
| 6：货损责任界定 | 原方案、签收与温度异常、处置记录可关联追溯 | 没有自动责任裁定、质量检验或赔付规则 |
| 7：绿色车队、共配、夜配 | 能耗、车型、班次与计费参数可配置，多门店合并配送 | 没有跨企业共同配送权益分配或夜间噪声/准入规则 |
| 7：温度、超窗、爆仓、故障异常与预案 | 温度异常、时间窗与空间超限可提示；约束失败留原因并允许调整输入 | 车辆故障没有专门的救援调度流程，不能称已覆盖全部异常 |
| 7：主数据、数据质量、系统底座 | 字段、单位、整店身份、维度与来源校验；不静默补齐缺失资料 | 企业SKU/门店主数据映射和正式数据质量规则仍需真实接口 |
| 7：高频、稳定、可复现和规模化求解 | 结果确定、批次可复算；构造实体与放置预算明确；预算耗尽不称无解 | 当前工作台每仓12门店、4车的范围未扩；不能承诺大规模分钟级性能 |
| 8：TMS、订单、车辆、充电与温度系统集成 | 输出本地交接包和配送清单，保留输入与结果版本 | 企业接口未接通，也未向司机端正式下发 |
| 8：地图、装载图与路线图 | 本轮由地图与车厢可视化专项实施，直接关联算法门店顺序、箱位与动作 | 应以最终浏览器验收截图和交互记录为准，不能只依赖代码存在 |
| 8：人工调整、复核、保存与导出 | 同仓调车调序生成新候选并重核；确认、保存和导出独立 | 已有事实记录的输入锁定；冷链空间任务在途改序仍不开放 |
| 8：异常、缺数据、不可行时兜底与人工介入 | 返回具体缺项或失败，支持规则修订和人工候选，不擅自放宽硬约束 | 有限搜索失败只是未找到，不能证明业务无解 |
| 8：多行业、多港口、车型与计费扩展 | 分仓组织、箱规、温区、能耗、车辆和费用独立配置 | 可配置不等于已完成多行业现场部署 |
