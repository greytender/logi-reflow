# CSV场景AI事件合同

2026-10-11。本机只读理解接口 `POST /api/dispatch/interpret`，传当前场景 `id`、`revision`、1–500字 `message` 和最多4条 `context`。服务端读取最新保存场景，不接受前端上传订单表替代当前状态。理解前校验修订，返回前再次比较场景编号与修订；变化时409，不交付过期结果。

## 支持的事件

- `urgent_order`：发生时间、原始目的门店编号、货在仓库的明确说明、每行SKU/箱数/每箱kg/每箱m³、承诺与截止。缺字段或某行缺值会补问，服务端不补默认值。目的地不能是E01/E02；编号由算法避开现有占用后分配，最多两个已采用新增货单。
- `time_window_change`：发生时间、准确订单编号、新开门/承诺/截止。可修改未签收E01/E02；已签收订单拒绝，已卸货不能把开门时间改到卸货开始之后。同店多单应注明是哪一单。

时间格式HH:MM，当天00:00–23:59；发生时间不能早于场景时钟。早于08:00、自定义门店编号均可；不是原讲解模式的固定编号/时间。新货整单配送，不支持拆单、跨车现场接货、新地址和连续故障。

多个事件、故障、非仓库新货、歧义或不能判断的输出应为unknown并要求澄清。模型是否遵守这些要求依赖其质量，服务端还会做结构和已知状态校验；人工核对仍不可省略。字段校验通过不代表路线可行。

## 使用流程与边界

理解成功只返回结构化事件，没有SQLite写入、候选、采用或执行。网页显示中文字段核对摘要；勾选后才提交普通 `/api/dispatch/event`。该接口重新验证修订与业务约束，使用现有有限启发式生成候选。完整候选经路线核对后才可采用；不完整候选保留原计划。AI不输出可直接执行的路线。

请求外部DeepSeek时，只发送当前业务消息、最多4条补问原话、原始门店编号、紧急订单与目的门店编号对应、已签收编号。不发送完整原始SKU、车辆、道路或路线表。场景刷新/回执/采用后清理旧草稿与补问上下文。当前数据均构造；未来企业使用这些编号/消息前需脱敏并确认数据授权。

接口返回模型、调用延迟以及服务商提供的token用量；拒绝的CSV草稿也保留可获得用量。凭据仍仅服务端环境，现有项目DPAPI脚本负责注入。接口错误不自动重试。费用未按价格核算，token用量不能等同人民币费用；服务端发生读取/网络错误时可能无法获得用量。

## 无密钥复现与真实验证

`python reproduce_csv_checkpoint.py`使用临时数据库和固定草稿验证字段至配送执行，完全不调用AI。

真实验证需要空的隔离数据库及18766服务：

```powershell
./start.ps1 -Port 18766 -Database outputs/my-csv-ai-isolated.sqlite3
# 在另一个终端运行；只允许该隔离端口，不写8766
python verify_csv_ai_live.py --allow-isolated-writes
```

第二条会产生真实API用量，并在隔离库创建与执行模拟场景；不自动重试。正常 `./start.ps1` 仍使用8766和原运行数据库。不要将隔离测试写入真实调度历史。
