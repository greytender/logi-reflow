# 同批人工排车对照

现有赛方托运单和答疑提供了订单及人工调度现状描述。同批人工分车、站序、完整排车用时和实际回收记录仍待提供。原托运单继续走原表核对流程。

## 所需输入

1. 准备一个单仓、一个配送波次的批次 JSON。顶层 `data` 使用应用已有订单、车辆、路网、时间窗、费率和包装合同。可加 `loading_profile`。同店归并、箱规、路网和回收规则应在试算前核对。
2. 在批次中填写 `search_scenarios` 和 `evaluation_scenarios`。每个情景以门店 ID 为键，值为 `{"cartons": 纸箱数, "totes": 周转箱数}`。情景中未列的门店沿用名义回收量。独立评估情景应在算法运行前锁定。真实回收数据缺失时标记为构造压力情景。
3. 从同波次的调度记录抄录每台车的实际分配和站序。填明可核对的来源编号及从接单到形成可复核方案的秒数，缺失时填 `null`。真实记录填 `operator_record`，构造样例填 `simulated`。

```powershell
python -X utf8 same_batch_comparison.py --batch batch.json --baseline-template | Set-Content -Encoding utf8 baseline.json
python -X utf8 same_batch_comparison.py --batch batch.json --baseline baseline.json
python -X utf8 same_batch_comparison.py --demo
```

模板固定订单、车辆、道路、规则和箱规的指纹。批次改动后，应从原记录重新核对对应关系，再生成模板。工具拒绝漏店、重复店、未知车辆以及未通过名义约束的基线。人工基线在模型里无法通过时，应回查差异和现场作业规则。对照输出装载率、算法耗时、运费试算与留出回收情景通过数。人工流程耗时独立列出。建议实际操作时同时记录算法侧的数据准备、系统计算和人工复核用时，按同一口径对比。
