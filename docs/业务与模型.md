# 城配续航：当前业务与模型

更新：2026-10-12。唯一应用为http://127.0.0.1:8766/。历史稿保留在业务与模型-20261011历史.md；其旧状态不作为当前判断。

## 问题与输入

配送中心调度员需要在出发前判断车、货和路线能否共同执行；出发后调整不能抹掉原坐标、货物归属与签收事实。输出为可核对候选、装卸步骤和代价，采用由人决定。

交付输入全部构造。四份CSV提供SKU订单、车辆、静态有向道路与设置；loading.json显式提供箱规、朝向、易碎、承重与可用长方体车厢，不从商品名或AI猜测。字段见企业离线试算入口.md及CSV-AI事件合同.md。

## 约束、费用与搜索

路线核验重量/体积、准入、班次、窗口、仓库取货先后与回仓。到达/完成窗口口径分开，承诺用于迟到，硬截止用于可行性。CSV沿用导入卸货时长与有向道路，不生成虚构GPS位置。费用为构造出车费、公里费及独立故障试算中的模拟转运费，不是完整企业成本。未安排、迟到、费用、改动及求解时间分别报告。

`normal.py`、`matrix_dispatch.py`采用多起点插入与有限移位；`loading.py`在候选路线内核验箱体，按逆配送顺序及三种有限排序尝试箱体面角点。最多80箱、200000次放置检查预算；缓存绑定一次请求中的车辆和有序路线。失败不推广为所有排列无解。

装载采用整厘米坐标，检查车厢边界、不重叠、允许的水平90度旋转、易碎零上压、单箱全底面支撑、支撑链累计承重与尾门沿+x直线卸货。不能免费倒货或先移走支撑箱。体积一致容差为0.1%或1e-7m³。`loading_audit.py`不导入装载求解器，从坐标独立重放每个装卸中间状态。

单箱/两箱允许朝向枚举的几何否定只证明该限定范围不可行；多箱启发式失败标为未找到或预算触顶。不保证全局最优，未实现完整EP、ALNS、强化学习或精确求解器。方法依据见智能配载方法筛选与实现.md。

## 在途状态与执行

固定装载模式由`fixed_loading.py`冻结尺寸、车厢、坐标与原货归属。收货变化改序只核验原摆放，采用前再复核；整单签收后才移除箱体。固定模式拒绝新货插入，不能拿总体积代替剩余空间核验。

普通CSV模式最多两个已采用仓库急单，各有独立SKU、编号和取货任务，每批8分钟装货；装完前归仓库，装完后归车，签收不释放两单额度。原货不换车，途中先完成当前道路段。该模式没有3D保证。独立故障试算要求接货车先到故障点；连续故障、固定模式故障转货未接入。

候选、核对采用与执行分开。候选不改变货物和事实；过期修订、重复采用与执行后的旧候选被拒绝。不完整候选不得采用。采用版本保留快照，当前预测另存。到达、开始卸货、整单签收逐步人工模拟确认，时钟不自动签收。迟到签收仍保留事实，剩余预测不可行时标需要重排。

## 架构与AI分工

`server.py`使用标准库HTTP绑定本机；web为原生JavaScript/SVG。`scenario_workspace.py`用独立临时状态管理主应用交互，闲置两小时或重启失效，刷新需重新开始；专业工作台的`continuous.py`、`store.py`以SQLite保存场景、版本和修订号，旧场景不迁移。

AI只提取字段、补问或拒绝歧义；服务端根据保存状态再次校验，人核对后本地算法生成候选，人另行决定采用。字段有效不代表路线可行。DeepSeek历史构造真实调用记录不证明普遍准确；本轮没有新增真实调用。临时密钥仅内存保留一小时，HttpOnly/SameSite=Strict标识和本机同源限制不代表生产安全体系。

## 证据与缺口

几何反例：48元方案不可执行，117元联合方案通过。固定坐标反例：A→C→B卸不出，A→B→C保留45分钟迟到，两方案均38元。易碎/堆叠反例保留未安排订单。六店十二箱完成十八条脚本模拟回执及回仓。

28组异常、56份独立核算构造方案保留20组无变化与不利结果。已有185项回归和13组Chrome验证属于前轮，本轮交付验证单独记录。未证明原创算法、企业收益或一般规模性能。

未实现或待验证：固定空间新货、连续故障、温控、轴荷、多箱共同支撑、侧门、现场可达性、真实接口/回执、成熟求解器/标准算例对照、更大3D规模、完整企业成本和实际收益。
