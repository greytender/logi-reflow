# 城市配送智能配载：主线、复用与业务接入

2026-10-12，按用户最新偏好调整：先形成整体可运行粗版，再逐项改善；主线仍是城市配送智能配载。初赛不接真实业务，但要使后续授权数据接入容易。原有代码、历史数据库和验证证据保留。

## 官方场景核查与范围

本轮通过Codex浏览器技能实际连接用户现有Chrome，读取正在打开的物流页面，并展开三个补充场景。重点推荐包含运力/路线、多约束装载、3D与装卸三部分；公路港招商、无人车调度、视觉量方称重是另外三个可选方向，不是全部必做模块。数据示例仍标终赛提供。来源与读取摘要见`evidence/logistics-track-source-20261012.json`，不是只凭标签页标题判断。

主问题：中心仓收到每日多SKU订单后，如何共同核对车辆、路线、货物摆放与装卸；出发后遇到变化时，如何保留原摆放、货物归属与执行事实，给出可执行候选和代价。

新加scenario_demo.py及scenario.html只是整合入口，运行完整粗版不覆盖本机已保存场景。现有normal.html和loading.html仍是详细操作工作台。故障独立试算继续保留，未宣称连续故障已实现。

## 整体粗版已经跑通

五份明确输入 → 有向道路/时间窗与运力 → 联合路线和装载 → 可用车厢空间与载重占用 → 3D与装卸步骤 → 固定坐标连续状态 → 构造改窗候选（不采用） → 正常计划脚本模拟到达/卸货/签收 → 回仓 → 交接与JSON导出。

六店十二行SKU十二箱案例，含易碎和普通箱，SMALL/LARGE两种车型。联合方案选LARGE，SMALL留仓；48kg、载重占用96%、长方体空间占用30%、模拟运输费108元。18条脚本模拟回执、09:31回仓，坐标保持、重启读取一致。这是实现验证；没有证明空间利用率或运输成本已经最优，也不是企业效果。更多门店/箱体通过原CSV导入，不用默认小样例冒充规模能力。

## 未来业务的连接合同

| 数据/事件 | 当前可用入口与单位 | 后续真实来源候选 | 接入前必须解决 |
|---|---|---|---|
| 订单与SKU行 | orders.csv；quantity箱数、每箱kg/m³、收货窗口、卸货分钟、准入 | 授权TMS/WMS脱敏导出 | 企业订单/门店/SKU映射、取消/拆单/混箱口径；当前按整店完成 |
| 箱体包装规则 | loading.json；整厘米、保持向上水平旋转许可、易碎、累计上方kg | 包装规格与现场认可规则 | 不能从商品名或总体积猜尺寸；易碎禁压与单箱全底面支撑是本模型边界 |
| 车辆与车厢 | vehicles.csv＋loading.json；kg、m³、可用长方体cm、班次、费用 | 授权车队车辆主档 | 轮包、侧门、非长方体、轴荷未建模；费用仅固定费＋公里费 |
| 配送道路与时间 | travel.csv；有向distance_km/travel_minutes | 授权道路矩阵或地图导出 | 版本、生效时间、道路准入与交通更新；当前不会从地址自动生成矩阵 |
| 业务异常消息 | CSV专用AI理解合同＋结构化表单 | 调度员录入、授权TMS事件 | 模型只提取/补问；校验、核对、候选、采用分离；真实消息质量待验证 |
| 装车与摆放确认 | 当前固定装载manifest是假设按布局开始的人工模拟 | 仓库/WMS装车确认 | 真实确认时间、货物扫描、现场偏差与坐标；真实装车回执接口未实现 |
| 执行回执 | 当前仅source=manual_simulation；到达/卸货/签收三步，带修订保护 | 司机APP、电子回单、仓库/门店事件 | 设备身份、鉴权、去重、乱序/撤回、时钟与部分签收；真实source会被现有接口拒绝 |
| 位置与成本反馈 | 当前道路段、累计里程和模拟运输费用 | 授权GPS、执行日志与结算规则 | GPS不能当签收；预测与回执分开；真实人工、货损与结算成本另建 |

现有离线合同及校验已实现；企业字段适配器、连接器、实时接口、鉴权和真实回执均未实现。当前原CSV上限40店/10车，3D最多80箱、放置候选预算200000；这些是原型上限，不是企业规模承诺。若后续数据超限，应先补性能与基线，不能直接以压缩SKU或漏订单规避。

## 扩展场景的位置，非必须任务

量方识别更接近主线，可作为箱规采集前端：输出待确认的尺寸/体积、测量方法与不确定性；未经确认不能进入硬约束，图像也不能可靠替代称重。现在没有视觉模型。

无人配送可作为车辆/位置/回执来源：需另建续航、充电、道路通行和无人车异常合同；目前通用车辆路线模型不能称为无人车真实控制。招商匹配与主线较远，暂不建。

## 逐轮改进与潜在贡献

下一轮优先把“核对联合方案 → 仓库装车假设/确认 → 创建固定场景 → 司机/门店回执”的角色交接做顺，保留当前接口保护。之后补固定空间新货插入、统一普通CSV/固定装载异常流程、同数据的路线/装载基线与规模评估，再考虑真实授权数据离线回放。每轮先填主流程缺口，不为单个小细节无限加深。

题设已经要求路线、配载与3D，不能作为本项目原创。潜在可验证贡献是把在途原摆放、货物归属与执行事实一起约束异常决策，让不能卸货、不能凭空上车或过期候选被拒绝，并记录时效/费用取舍。基础算法、工作台与接口整理属于工程实现；原创性与行业独特性仍待查新和对照。

对评委展示应围绕完整业务流程、实际决策变化、失败反例、可复现证据与真实接入前提。评委是否青睐、真实节省多少成本和获奖机会尚不能确认；初赛可以用构造数据证明功能，但不能据此证明企业收益。
