# 比赛要求核对（2026-10-10）

来源：工作目录 `官网全文提取.txt`、`官网原始页面.html`；在现有 Chrome 实际读取官网 `#/logistics`、`#/guide` 正文。网页地址：http://asserts.dsdigital.team/static/transfar/transfar-dsgroup-ai-architect-hackathon.html 。通用网页抓取工具访问失败，已用 Chrome 正文完成核对。

## 已确认

- 物流赛道支持自主命题；重点推荐城市配送智能配载包含运力匹配与路线优化。动态调度与异常恢复在赛道业务范围内，首版没有覆盖推荐的 3D 装载部分。
- 五项评分各 20%：技术可行性与实现可信度、技术创新与效率提升、业务价值与场景契合度、工程化潜力与规模扩展能力、企业落地可行性与应用潜力。
- 提交入口是 GitHub 私有仓库链接，需邀请 DsChHack 为 Collaborator；需代码、README 与运行说明。README 需团队信息、业务场景、核心方案、应用价值。
- 需明确算法、模型、架构、数据来源、外部依赖、运行方式、测试结果和限制；Demo 可选。需标注模拟数据和人工操作。
- 官网写明提交作品知识产权归主办方；真实数据后续使用受赛事保密规则约束。

## 未确认

- 48 小时建议来自用户对负责人的转述，官网已读页面没有写同样时限；赛事最终截止日期、具体提交渠道未核实。
- 项目创新性、企业收益、晋级或获奖概率均未核实。当前只评价技术实现与可验证性。

## 评分对应的当前证据和缺口

技术可信度：有本地代码、约束测试和完整结果；真实 AI 与更多异常尚未实现。

创新与效率：有“顺序追加接货”对照，体现迟到/成本取舍；没有完成同类方案调查，不能宣称新算法或行业首创。

业务价值：明确调度员、在途故障和接货流程；收益仅在模拟条件内，需访谈确认实际流程与费用。

工程扩展：前端、接口、算法已分离；0.2 已增加 SQLite 事件/计划快照、采用/撤回记录和过期页面保护。枚举的阶乘复杂度仍是瓶颈，需要后续限时求解器、连续异常推进和执行回执，未证明大规模性能。

企业落地：本地可运行，无外部模型依赖；缺真实订单/状态接口、身份权限、持久化、现场接货规则和企业试验。

未进行外部发布、仓库创建、推送、邀请评委或赛事提交。这些动作仍须用户确认。
