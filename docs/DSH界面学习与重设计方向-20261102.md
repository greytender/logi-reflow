## 从官方实现得到的设计依据

1. 输入器有明确发送、接收、失败及草稿保留状态。并非每次重画消息后再造一个 textarea；失败不能丢输入，运行时有明确控制。
2. 文本回复、准备中的工具、已派发工具和工具结果有独立呈现。工具名称出现不等于开始执行，过程状态由真实事件决定。
3. 过程按轮次分组，运行中显示当前活动，结束后可收起，关键回复和成果保留。系统提示、一般上下文注入不挤进普通 Chat。
4. 工具结果有业务专用视图；通用文本只是没有专用视图时的回退。真实参数、结果和阶段是展示依据。
5. 对话、成果预览、轨迹检查分别承担协作、查看成果和排错职责。侧栏可收起、按需展开，保护主要内容宽度。
6. 正常查看和历史恢复使用同一事件依据；流式文字是其中一种更新，不等于整个工作流。

## 本平台拟采用的产品结构（设计推断，尚未实现）

- 首页/工作概览：继续最近批次、新建或导入、需要处理的异常。没有业务任务时给清晰入口，不默认填充模拟成绩；样例独立进入。
- 批次工作区：围绕一批真实任务工作，路线/地图为主视图，订单、车辆和执行详情按当前选择展开；AI 可侧边协作，可按需要调整空间。
- 资料与规则：原始订单核对、车辆、仓库、包装和计费配置有独立入口，不长期铺满业务主视图。
- AI 输入：支持明确引用当前批次/车辆/门店，清楚表示作用对象；这些引用尚需开发，不能只装饰成可用按钮。
- AI 过程：检查数据、排车、核验、解释分别显示真实状态；缺项请求形成就地补充操作，详细日志按需展开。
- AI 结果：返回可打开的候选方案、费用变化、具体风险和对应操作。对话只作短解释，具体数值由核验后的工具数据渲染。
- 异常与恢复：保留失败输入、重试入口与已完成工具结果；取消与重试需要业务版本约束，不能只在浏览器停止动画。

不照搬开发工具的代码终端、插件管理或调试术语。地图尚缺经纬度，现有路线图只是明确标注的关系示意。

## 当前技术进展与差距

DeepSeek API 适配已写入 deepseek_agent.py，使用官方 deepseek-flash，服务端调用，现有临时密钥/加密本地配置继续可用。自然语言请求可选择白名单工作流并执行真实计算、独立核验，再结合汇总结果解释；保留最近三轮对话。模拟数据真实 API 联调和浏览器发送路径均已成功。不是 DSH runtime 集成。

现有请求仍为非流式、整轮完成后保存，未实现上述事件流、停止/恢复、业务结果组件与页面分层。不能宣称已具备 DSH 级交互。已有 API 实测证据在 outputs/deepseek-agent-qa/live-verification.json；模拟数据的费用比较不代表企业收益。
