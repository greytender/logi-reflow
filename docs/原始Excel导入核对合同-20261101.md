# 原始Excel导入核对合同

2026-11-01。实现入口为 `intake.py`，应用页面与HTTP路由由主应用集成。它负责本机原始订单资料的保存、追溯和缺项提示；不将原表自动变为可求解配送任务。

## 数据与保存边界

`IntakeStore(path).create(name, filename, content_bytes)` 解析并创建一个原始核对资料；`read(id)` 恢复完整核对文档；`list()` 返回列表摘要。每次创建分配独立编号，不自动将同名文件、相同哈希或同名门店合并。解析或校验失败不会留下半个核对资料。

资料保存于独立SQLite表 `intake_documents`，包含可序列化的完整核对JSON及原文件字节 `source BLOB`。源字节逐字节保留，SHA256对应上传字节，不对应转换后的JSON。原附件不会被改写；源文件和数据库仍留在本机，不能据此宣称企业接口已经接通。当前导出提供核对JSON，不将源BLOB嵌入JSON，也不代表已实现JSON回导或备份恢复工具。

顶层字段为 `id`、`name`、`created_at`（UTC）、`status`、`filename`、`sha256`、`size_bytes`、`sheets`、`styles`、`formula_policy`、`audit`。内容中不补入仓址、车辆、道路、批次、回收预测或真实门店ID。

## 原值、单元格与合并继承

每个工作表保留名称、显示/隐藏状态、原部件路径、全部显式源行及合并区域。行保留原行号和隐藏状态。单元格保留Excel引用、列号、类型、原始值文本、解释值、公式、公式缓存状态、样式索引和合并来源。

- `raw_value` 保留XML原始值文本；共享字符串另由 `value` 给出解析文本。数值解释只为预览和核对提供方便，不能替代原文本，例如高精度数值或未来需要确认的日期序列。超JavaScript安全整数或转换会舍入的数值，其 `value` 也保持原文本并提示精度核对，避免JSON网页显示先发生舍入。
- `value` 是该原格自身的值；不因合并或缺项提示而改写。`effective_value` 仅在原文件明确的合并区域内继承首格，`merged_from` 记录首格引用。合并外空白不向下填充，不补成零。
- 稀疏XLSX可能不写出合并区域内的空格。实现仅在原本存在的源行中物化这些预览格，并标记 `source_cell_present=false`；这不是新建订单或源行。
- 合并区域非首格仍有原值会保留冲突并提示核对；区域重叠或复杂度超过本地上限则拒绝整个导入，不选择性丢弃部分合并。
- `styles` 保留格式编号与自定义格式代码。当前不执行完整Excel日期、颜色、字体、富文本或打印布局渲染，不把样式数值默认转成业务日期或计量单位。

## 公式缓存与外部资源

公式保存为 `{text, attributes}`，缓存状态为 `cached`、`missing` 或非公式 `not_formula`。本地不执行公式、不重算缓存，不访问公式或关系指定的文件/网址；缓存存在不证明结果最新或业务正确。无缓存公式的值保留未知，并进入核对提示；数据行只有无缓存公式时也保留在识别行集合，不漏计为“空行”。

仅支持 `.xlsx`。宏、加密、外部关系、外部工作簿链接、DTD/实体声明、重复压缩包路径及无效或缺失必要部件会被拒绝。包括外部超链接在内的关系当前采用保守拒绝策略，不是导入后联网读取。构造样例采用标准OOXML根关系和内容类型声明，但未用桌面Excel进行交互打开验收。

## 业务核对口径

当固定表头吻合时，`audit.profile=official_order_headers`，识别A:J范围的源数据行；这是表头匹配，不是企业真实性证明。第一张匹配表用于该摘要口径，其他工作表仍完整保留在原始预览中。若不匹配则 `generic_raw`，不猜测数据起始行、字段或单位，`record_rows=null` 并提示人工映射。

核对提示包括同名收货单位多行、序号缺口或重复、地址缺失/合并继承、带“推断”的名称、非负数字异常、冷链字段部分或全部缺失、条件性的冷链体积口径差异，以及配送必需字段尚缺。

名称字符串数量不等于已确认实际门店数。同名多行不删除、不归并；序号缺口不补造订单。冷链件数、体积和重量同时空白仍是未知，不能视为0。体积提示明确写出“若尺寸为厘米、体积为m³”的前提，不自行将原值修正为0.001或0.01。共享冷链运输箱仍需单独确认包装层级和设备能力。

`audit.issues` 每项提供 `code`、`message`、`sheet`、`rows`、`cells`、`severity`；`can_solve` 始终为false。当前是原表核对底座，不包括修改原字段、核对签字、字段映射编辑器、门店主数据归并、任务波次选择或转成正式求解输入的确认流程。

## 规模与拒绝策略

单文件最多5,000,000字节；解压后部件总计最多32,000,000字节；压缩包最多3,000个部件；工作表1—30张；全部工作表最多10,000个显式源行、200,000个源格及合并物化预览格。每张表最多2,000个合并区域，单个合并面积不超过200,000格，合并扫描工作量另设5,000,000预算。超过限制时拒绝整个文件并说明需要明确拆分，不静默截取前12行或部分工作表。

这些限制是本地原始核对的资源边界，与任务工作台的12店/4车求解限制不同。完整预览116行不证明已经完成116行的门店归并、求解或物理装载验证。
