# 执行位置与等待记录合同

2026-11-01。该合同对应本地任务工作台的人工/模拟观察，不是GPS轨迹、到店签收、司机接口或真实履约证明。

## 写入接口

`ApplicationStore.observe(task_id, revision, observation_record, reviewed)` 在当前任务修订上追加一条观察，并原子提交新修订。`reviewed` 必须为布尔值 `true`；旧修订请求返回冲突，不覆盖新内容。

```json
{
  "vehicle": "TRUCK_2",
  "kind": "wait",
  "node": "STORE_001",
  "observed_at": 630,
  "source": "simulated",
  "note": "构造演练：司机报告仍在该节点等待"
}
```

- `vehicle`：必须是当前已确认完整方案中有配送任务的车辆。未确认、无配送任务或已记录回仓交接的车辆不能追加观察。
- `kind`：`position` 表示人工报告车辆位于一个已知节点；`wait` 表示仍在当前起算节点等待至所填时刻。
- `node`：只接受本车原已确认路线中的门店节点及仓库节点，不接受其他车辆专有门店、任意坐标、路段中点或新地址。`wait` 还要求节点与当前有效锚点相同；移动节点应使用 `position`。
- `observed_at`：当天0—1439范围内的整分钟，不接受布尔值、非有限数字或小数；不得早于本车最近回执、有效观察或班次开始。它是报告的时刻，不是系统从GPS获得的实测时间。
- `source`：只支持 `simulated` 和 `manual`。构造任务只允许模拟来源；企业来源声明任务可人工录入，人工来源必须填写备注中的单据、司机消息或其他信息来源。人工声明仍待真实性核对。
- `note`：字符串，最多500字；不把备注中的指令当作调度操作执行。

单任务最多500条观察。系统保留每条记录的唯一编号、原方案编号、车辆、来源、备注、时刻、保存时间、当时本车回执数量、剩余路线版本及保存后风险。当前入口不提供观察撤回或覆盖操作；错误记录更正仍需另行定义追加更正合同。

## 锚点与执行事实

每辆车的剩余预测按以下顺序选起点：

1. 若有在该车最近一条回执之后追加的观察，使用最后一条观察的节点和时刻。
2. 否则使用该车最近回执的节点和完成时间；回仓回执节点为仓库。
3. 尚无执行记录时，使用原计划仓库与班次开始时间。

观察记录保存本车当时的回执数量，防止另一辆车签收后错误地丢弃本车位置。新签收回执会自然取代之前观察作为起点；新回执完成时间不得早于本车当前观察时刻。新观察可继续更新新的起点。

观察不签收、不卸货、不回收、不交回仓库、不改变货物归属或已收包装。即使观察节点是下一门店，门店仍留在未签收列表；仍需单独保存整单签收和回收回执。即使观察节点是仓库，也不等于回仓交接，车上货物和包装不会自动消失。

观察节点与下一门店相同时，进入该门店的道路距离和时间为零，仍保留该门店的服务时间、窗口和先卸后收载荷计算。仓库与当前节点相同且没有后续门店时，回仓道路也使用零值，不要求输入不存在的 `A>A` 路段。

## 预测、候选与来源

`execution.view(task)` 顶层提供 `observation_count`。每车提供 `anchor={kind,node,time,id,source}` 和该车 `observation_count`。锚点 `kind` 分别为 `observation`、`receipt`、`shift`；班次锚点来源为 `planned`。

首条观察与首条签收一样冻结原输入及原方案：不能改写货物、车辆、道路和业务规则，不能调用全量出仓重算或切换原方案。仍可保留事实后生成同车剩余路线候选。

候选保存观察数量，服务端指纹包含观察历史。新观察会使此前未采用的候选失效，即使观察节点或时刻与上一条相同，也不会允许旧候选绕过核对。兼容旧任务：没有观察或观察列表为空时，保留原指纹构造；旧任务无需迁移数据库即可读取、继续签收或追加观察。

剩余路线的独立核验自行选取有效观察起点，独立重算道路、时间、货物和包装，不调用预测函数计算核验结果。当前已经超容或剩余窗口失效仍不能采用候选；记录更晚的观察不会清空包装或修复真实容量问题。

剩余预测CSV附带预测起算节点、分钟、类型和来源。已签收门店可作为起算节点出现在来源列，但不得重新出现在“门店”配送列。JSON保留完整观察历史。原配送CSV仍为出发前预测，不根据观察重算结算运费。

## 已验证与边界

`tests/test_observation.py` 包含13项验证：观察不签收或改载荷、同节点零路段、等待推进、独立核验一致、保留已收包装、观察使候选失效、回执时间不得倒退、首次观察锁定输入、非法或旧修订请求不写入、人工来源要求、已回仓车辆拒绝观察、仓库位置不等于卸货、当前超容/过晚仍不能采用、导出来源、旧指纹兼容及车辆间观察隔离。相关原有执行和剩余路线测试保留。

尚未验证或实现：任意路段位置、GPS轨迹、实时路况、自动签收、部分签收、观察更正、回收转运、温控、原箱体坐标与可卸性。系统不依据构造道路时间否定人工报告的位置，也不因人工报告被保存就证明车辆实际能在该时刻到达。观察只替换预测起点，之后道路与服务耗时仍是原任务中标注来源的输入。
