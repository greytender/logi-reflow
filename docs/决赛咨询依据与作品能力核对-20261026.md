## 2. 对作品完整业务链的理解

当前作品覆盖：明确输入 → 出发前选车、订单/路线与装载联合检查 → 根据坐标生成3D与装卸步骤 → 创建模拟出发状态 → 理解或人工录入异常 → 校验与人工核对事件 → 计算候选 → 单独采用 → 模拟到达/卸货/签收 → 只读交接与历史留痕。

这里有几条并列能力，不能合并成一项已全部打通的生产能力：

1. **出发前联合规划**：四份文件加loading.json，按有向道路、窗口、准入、班次、重量/体积与箱体规则核验车辆和有序路线。装载会影响选车和路线，并非只有3D展示。
2. **固定装载连续模式**：冻结箱规、车厢、坐标和原车货物归属，收货变化只在原摆放下核验；到达/开始卸货不释放货物，整单模拟签收后才移除箱体。新货空间插入未实现。
3. **普通CSV连续模式**：可导入多SKU、有向道路和车辆规则，支持连续收货变化及最多两个仓库急单；保留仓库取货先于配送及批次身份。只核验总重量和总体积，不能保证三维可行。
4. **单车故障独立试算**：接货车先到故障点再接货，具有模拟转运时间/费用。它未接入固定装载连续主流程，早期独立模块的模拟位置和完成约定也不能替代CSV分步回执。
5. **AI辅助输入**：可选DeepSeek提取事件字段和补问；服务端按当前状态校验，人先核对事件，再核对候选是否采用。无密钥可手工填写；AI不直接生成可执行派单。
6. **工程与交接**：SQLite场景、采用版本、修订冲突和旧候选失效保护；分别展示预测与模拟事实，按角色输出下一步。主应用临时场景与专业工作台持久化场景的保存方式不同。

路线方法为多起点插入、单订单移位与有限搜索；装载为逆配送顺序和三种排序的面角点构造。独立核验模块重新核算几何、承重支撑链与装卸中间状态。并未实现完整ALNS、强化学习、精确求解器或全局最优证明。

## 3. 哪些可以作为作品特色，哪些还不能称为创新结论

**可核查的实现特色一：把可装、可卸带入车辆和路线决策。** 三维图使用求解和核验所得坐标；低价路线若装不下，会被识别。这是实际行为，不只是展示形式。但联合路线与装载本来就是赛题要求，不能仅凭实现这一步宣称行业首创。

**可核查的实现特色二：在途变化尊重原摆放、货物归属与执行事实。** 调整时没有把货物免费换车或重摆，也不撤销已签收历史；原摆放下卸不出的更快顺序会被拒绝。这是本作品值得重点解释和验证的工程机制。其行业独特性尚待现有系统调查，业务价值更依赖现场是否允许倒货、能否取得真实装车状态。

**可核查的实现特色三：候选、人工采用、执行与核验分别留痕。** 不完整结果和无改善结果保留，候选不自动成为执行指令；状态变化使旧候选失效。此类保护有助于可审查性，但不能把通用工程做法直接当作原创算法。

**AI的位置明确，但提效仍需实测。** 历史材料有构造消息的真实调用记录，不能据此推断现场总体准确率或人工时间改善。本轮只做本地及模拟模型响应测试，没有新增真实模型调用。

因此，问题清单没有让业务方替你判断“是不是创新”，而是通过G09、S01了解现有做法，通过S05/S06检查关键假设，再通过S11判断是否产生可验证增量。

## 5. 问题如何覆盖决赛需要解决的不确定性

- **问题是否真实、用户是谁**：G01—G03、S01；避免仅靠赛题示例或虚构故事定义需求。
- **数据能否支撑算法**：G04—G07、S02—S04；核对包装件、车辆结构、业务时点和规则，避免从总体积或商品名称推测几何。
- **固定装载假设是否成立**：S05、S06；允许倒货时要核算代价，没有实际布局时不能冒充坐标已确认。
- **异常流程是否值得扩展**：S07—S09；按业务频率决定新货、改窗、故障和部分签收的优先级，不默认全部在决赛前开发。
- **AI与现有系统能否产生增量**：G09、S10、S12；分别验证消息理解与算法决策，选择使用人员能接受的输出形态。
- **价值能否可信证明**：G08、G09、S11；区分企业计划和实绩，用事件当时的已知信息开展同任务、同约束比较，保留不利结果。
- **怎样合法、可持续地接入**：G10、S12；落实官方已有数据规则、责任与人工兜底，不默认可上传外部服务或直接生产派单。

## 6. 对“体系化、以小见大”的处理

可用于沟通的链条是：货源与承诺形成需求 → 上游到货/分拨决定货物就绪 → 城配选车、路线和装载形成可执行计划 → 异常及现场反馈修正剩余任务 → 签收与成本记录用于履约复核。

这只是组织问题的待验证框架，当前作品未实现货源获取、港内分拨优化或结算系统。本次通过G01/G02和S01追问真实上下游依赖，通过G08/S11核对影响指标，而不将“以小见大”误写为重做全链路平台。

如果现场倒货成本很低、实际包装与箱规不匹配，或已经有成熟系统充分覆盖原摆放改序，当前方案的重点可能需要调整；应依据答复收敛到真实缺口，不先认定固定坐标一定是最重要痛点。
