# 从讲解案例走向企业数据试算：第一步

2026-10-11。本轮依据实际Chrome读取的官网AI＋物流页。主推荐是城市配送智能配载，示例为中心仓向30家连锁药店配送数百个SKU；订单、车辆、配送网络和装载调度规则是官网列出的数据类别。这些是场景依据，不是企业已经交给我们的数据或规则。

## 本轮完成什么

新增本地CSV试算入口 `pilot.py`。企业可将自己的脱敏表转换为约定格式，在本机计算，不上传第三方，不调用AI，不修改现有SQLite、不实际派单。示例在 `examples/pilot-30`，30个门店、5辆车、300行SKU，全部为自制模拟数据，道路表也是构造数据。

不再依赖固定S01–S12/V1–V3编号；本入口支持1–40个门店、1–10辆车。多SKU按门店汇总重量/体积，整次门店配送由一辆车完成。不能把它写成支持不同包装、分批、SKU堆叠、易碎或冷链规则。

正常规划重用原有限插入算法，最多5个起点、2轮局部移位，并把简单追加结果作为保底候选。导入有向的公里/分钟矩阵，不用直线或速度补缺。道路方向可不对称；删去一站的捷径也可能更慢，搜索已处理这种情况。

支持每店卸货时间、门店允许的车辆、每车出班与回仓收班时间。可选择到达或卸货完成作为收货承诺/截止的判断时刻。费用仅固定出车费和公里费；等待、卸货、加班等人工费用尚未计入。

## 怎样运行

在 `logistics-demo` 目录执行：

```powershell
python pilot.py examples/pilot-30 --output outputs/pilot-30
python pilot_benchmark.py
python -m unittest discover -s tests -v
```

企业试算时，将四份文件放在项目外的单独目录，再把目录路径传给第一条命令。真实数据与输出不要加入仓库。默认输出在被Git忽略的 `outputs` 下；若自行改输出目录，需自己确保不纳入提交。

输出 `comparison.json` 包含输入摘要及SHA256、两种路线、逐站时间和独立复核；`route-stops.csv` 是搜索候选的逐站核对表；`unserved.csv` 是未安排原因和人工处理建议。没有自动接受、修改窗口、联系门店或派单。

## 四份输入文件

| 文件 | 内容和约定 |
|---|---|
| orders.csv | stop_id、sku、quantity、unit_weight_kg、unit_volume_m3、open、due、close、service_minutes、allowed_vehicles |
| vehicles.csv | vehicle_id、max_weight_kg、max_volume_m3、fixed_cost、cost_per_km、shift_start、shift_end |
| travel.csv | from_id、to_id、distance_km、travel_minutes；仓库与所有门店间每个非自环方向均须有值 |
| settings.json | depot_id、data_kind（simulated或enterprise）、travel_source、window_rule（arrival或finish） |

时间为当天HH:MM；公里、分钟、公斤、立方米分别按表头填写；数量为箱数，各SKU可有不同箱重/箱体积。跨日、缺货、拆单不支持。每个门店只访问一次；同一门店每行SKU须使用相同收货窗口、允许车辆及整次到店卸货用时，不将每行的卸货时间重复累计。允许车辆用 `TRUCK_1|TRUCK_2` 格式，留空表示全部已导入车辆。

门店、SKU、车辆、仓库编号以字母或数字开头，只使用字母、数字、下划线或连字符，最多40字符。企业中文名称可保留在企业系统，此入口使用脱敏映射编号。模板为UTF-8带BOM，便于Windows Excel打开；导入接受UTF-8带或不带BOM。

重复SKU行、冲突的同店规则、未知车辆、缺失道路方向、非有限数字、非法时间和重复表头均拒绝。`data_kind=enterprise`只是来源声明，不会让软件自动验证企业真实性。道路表是一个静态时间切片；必须记录来源和时段，不能声称实时路况能力。

## 对照和失败怎么读

基线是“按表中门店顺序，依次尝试追加到第一辆可行车辆”，不是企业现有人工计划。两方法用同一输入、同一约束，输出还会标注配送集合是否相同。集合不同的费用和迟到仅描述各自结果，不可计算同任务节省率。

搜索按未安排、迟到单数、迟到分钟、费用排序。没有解时区分：可到店车辆装不下；单店配送仍无法满足窗口/班次；有限搜索未找到。最后一种不能解释成数学无解。人工建议只能供核对，不能代表已执行处理。

独立复核不用求解器的路线评价函数，重算SKU汇总、车辆准入、有向路程、等待卸货、窗口、回仓班次、费用、迟到和订单唯一归属。仍基于相同输入数据，并不验证地图数据的真实性。

## 目前还不能怎样用

新入口是出发前的离线排程。0.8连续异常模块仍限12店3车、直线模拟和一个紧急单；本轮尚未把可导入数据、矩阵路程、多SKU带到连续故障和实时执行里。不能用新入口绕过这一限制。原网页与保存的场景不改写。

车辆真实位置、司机到达/卸货/签收回执、通行时段、续航/充电、休息、冷链、三维装载、企业TMS/WMS接口和企业现场价值均未实现或未验证。需要企业确认“到达是否等于交付”等规则，不能以模拟约定代替。

下一阶段优先将这一数据合同接到事件时刻的真实状态快照和连续异常模块，区分到达、卸货中、签收完成，并与企业提供的现有人工排程做同任务对照；在拿到合法授权数据前只能做构造验证。

2026-10-11后续补充：12店连续网页已实现三步人工模拟回执，见分步回执验证。CSV入口尚未接入；真实司机回执仍未实现。前文未实现状态为离线入口这一轮的历史说明。
