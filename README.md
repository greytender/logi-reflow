## 算法能力与反例

| 构造情境 | 当前结果 | 正确解释 |
|---|---|---|
| 重量/体积可行但几何不可行 | 48元方案装不下，117元联合方案通过核验 | 可执行性有代价，48元不能作为可执行降本基线 |
| 出发后重排 | 原摆放下A→C→B卸不出；A→B→C可执行，保留45分钟迟到，均38元 | 原坐标约束不能被更快的路线绕过 |
| 易碎/堆叠限制 | 部分订单未安排，保留失败且不允许采用不完整候选 | 不隐藏失败 |

常规路线使用多起点插入、订单移位和有限候选搜索。装载层使用逆配送顺序、三种有限排序与箱体面角点构造，`loading_audit.py`独立核验坐标、支撑链和装卸过程。有限搜索的未安排结果需人工核对。

回收算法试验使用 `recovery_search.py`，包含局部修复、标准 ALNS、冲突引导和多情景评分。运行 `python -X utf8 recovery_benchmark.py` 可复现[算法对照](evidence/回收联合排程对照实验.md)，运行 `python -X utf8 port_transfer_demo.py` 可复现[跨港端到端演练](evidence/跨港端到端演练.md)。回收情景检查逐站重量和体积，出发货物可选三维核验。

可选的 [PyVRP ILS 外部对照](evidence/PyVRP外部算法对照.md) 使用固定版本 0.13.1，走相同的本地业务与装卸核验。该依赖仅用于离线实验。

[中国城配四指标稳健性对照](evidence/中国城配四指标稳健性对照.md) 使用公开中国城配点位及距离矩阵构造波次，对比固定车队、逐车装载和运费护栏下的候选，并保留独立情景复验结果。

工作台 DeepSeek 助手调用白名单工具，候选由调度员核对后确认。在选中一个未开始执行的模拟仓后，可发送「对比局部修复和情景 ALNS 的回收压力试算」，结果作为对话记录保存。对话可逐轮归档、恢复或删除，能力范围外的回复仅在当次显示。可选 DeepSeek 调用需本人密钥并产生 API 用量。临时密钥在服务端内存保留一小时，浏览器持有 HttpOnly 会话标识。

## 状态与范围

主应用交互使用独立临时状态，闲置两小时或服务重启失效，刷新需重新开始，可先导出。专业工作台使用SQLite保存场景/版本，保留CSV导入、连续收货变化、普通CSV模式最多两个仓库紧急单、分步人工模拟回执、只读历史与交接、独立故障试算及联合装载。

固定装载模式冻结尺寸、坐标与原货归属，改序只核验原摆放；整单签收后才移除箱体。普通CSV模式只核验总重量/体积，不承诺3D可行。出发后不能切换模式绕过约束。候选不改变执行，推进执行使旧候选失效，已签收事实不能撤回。

尚未实现或验证：固定空间新货插入、连续故障、温控、轴荷、多箱共同支撑、侧门与现场可达性、真实TMS/WMS/GPS/司机接口、完整企业成本与收益。固定装载最多80箱，搜索预算可能触顶；30店CSV复现不等于数百SKU的3D规模证明。
