# 城配续航 · LogiReflow

从一张订单表，到一趟能核对、能调整的配送方案。

城配续航是一款城市配送调度工具，面向需要同时处理货量、车辆、门店时间、装卸顺序、冷链和空箱回收的调度员。导入订单后，可以核对原始记录、生成配车与线路方案、查看三维装卸过程，再确认方案、导出配送清单和登记执行记录。

## 打开使用

**Windows 用户：下载完整项目并解压，双击根目录的 `打开城配续航.cmd`。** 浏览器会自动打开本地网站，演示期间保持启动窗口开启，结束后按 `Ctrl+C` 停止服务。

`final` 是当前交付版本。它自带 Python 运行环境、页面资源、中文字体和演示数据，在 Windows 10/11 的 Intel/AMD 64 位电脑上无需另装 Python、Node.js 或其他依赖。使用新版 Edge 或 Chrome，可获得完整的三维展示。

也可以直接把 `final` 文件夹压成 ZIP 带走。在另一台电脑上**先完整解压，再双击里面的启动脚本**。页面、排车和三维装卸均在本机运行，离线可用。

如果浏览器未自动打开，复制启动窗口显示的 `http://127.0.0.1:端口/` 地址到浏览器。端口由程序自动选择，不需要自己配置。

遇到启动窗口消失或浏览器未打开时，使用 `final/备用启动.cmd`。它在常驻命令窗口中启动同一套服务，手动复制窗口中的地址即可访问。服务停止或报错后窗口继续保留，输入 `exit` 可关闭；Python 启动异常同时保存到 `final/runtime/data/startup-error.log`。

## 第一次演示怎么走

1. 在首页进入调度工作台，先看本批订单和全部车次。
2. 打开“订单核对”，查看门店合单结果，点门店名追溯原始表格行。
3. 打开“配车排线”，选择车辆，查看站序、时间、里程与费用明细；需要时比较历史方案或调整站序。
4. 打开“3D 装卸”，查看车厢、冷链箱、逐站卸货和回收空间，再进入配送过程演示。
5. 打开“回收返仓”，查看回收安排，登记签收、回收、温度读数及异常处置。
6. 条件变化时，先预览影响、保存修改，再重新排车、核对和确认。确认后的方案可以导出配送清单。

内置批次使用比赛提供的 116 笔订单，按已确认口径合并为 103 家门店，当前演示方案安排 16 趟配送。车辆、道路、箱规与时间参数用于试算，结果展示的是这些输入条件下的方案；费用和里程可以追溯到配置与计算过程。首页、工作台和算法讲解页都从同一交付目录启动。

## 能处理哪些事

- **订单整理**：读取 Excel，核对字段和单位，合并同店订单，并保留原始行号与来源。
- **配车排线**：结合载重、容积、时间窗、车辆班次及费用规则生成候选方案，显示未安排门店和约束问题。
- **装卸核验**：检查三维摆放、冷链箱占位、取货路径、临时落地位和搬倒时间；页面展示求解结果中的空间坐标。
- **回收与执行**：按先卸后收计算逐站载荷，记录签收、回收、返仓和温度异常；已有执行记录参与后续剩余路线判断。
- **方案管理**：保留版本、预览修改影响、核验候选、人工确认和导出清单。输入变化后，旧方案不能继续当作当前结果使用。
- **算法讲解**：提供技术图谱、算法说明和展示模式，便于演示时讲清数据如何进入计算、方案如何得到核验。

## 小航助手

工作台右上角的“模型接口”可配置 DeepSeek、Qwen、GLM 和 Kimi 的兼容接口。填写服务地址、模型名称与自己的 API Key 后，小航可以结合当前批次及所选车辆的计算数据解释费用、线路和约束。

模型问答需要网络和相应服务的账户额度。API Key 只保存在当前本地服务的内存会话中，停止服务后需重新填写；不会写入项目文件。未配置密钥时，界面会提示配置，其他调度功能照常使用。

配送方案由算法计算，最终调整和确认由用户操作。当前交付支持本地配送清单导出，企业 TMS、司机端消息和真实派单接口尚未接入。温度页面保存逐次读数与处置记录。

## 技术栈

**前端**使用原生 HTML、CSS 和 JavaScript，负责订单表格、交互操作和方案展示；SVG 绘制线路拓扑和技术图谱；Three.js 与 OrbitControls 展示车厢、货物及装卸过程。字体和三维库随项目提供，页面不依赖在线 CDN。

**后端**使用 Python 标准库提供本地 HTTP 服务、JSON API 和 Excel 解析。Excel 文件通过 ZIP/XML 读取，数据与方案通过 SQLite 保存，交付版核心流程不需要安装第三方 Python 包。

**求解层**由 Python 实现，组合构造式排车、有限候选搜索、站序调整和装卸核验，并独立检查方案是否满足当前约束。它同时考虑配送与回收过程中的载荷、空间和时间变化。仓库分别求解，方案和计算来源可以追溯。

**模型接入**通过 HTTPS 调用各提供方的 Chat Completions 兼容接口，把当前计算结果作为回答上下文。模型负责解释和辅助理解，方案计算与数据校验在本地完成。

## 文件在哪里

```text
打开城配续航.cmd          项目总入口，启动当前 final 版本
final/
  打开城配续航.cmd        可携带演示包的入口
  使用说明.txt            换电脑演示与恢复初始数据说明
  launch.py               服务启动与本地页面路由
  web/                    页面、样式、交互脚本、字体和三维库
  runtime/                Python 服务、求解算法和业务模块
    docs/reference-materials/  本批原始订单与试算参数
    data/                 启动后生成的本地工作数据，不提交到 Git
  demo/                   首次启动使用的初始演示方案
  python/                 Windows x64 独立 Python 运行环境
scripts/                  开发验证和打包脚本
tests/                    自动化测试
docs/                     设计与实现说明
```

仓库根目录的 Python 模块和 `web` 保留开发工作台，当前成品以 `final` 为准。开发工作台可通过 `python server.py` 单独启动。

## 数据保存和恢复

首次启动会把 `final/demo` 中的初始方案复制到 `final/runtime/data`。之后的修改只写入本地工作数据，刷新页面或重启服务会继续使用这些记录。

需要恢复初始演示时，先停止程序，把 `final/runtime/data` 改名为 `data-backup`，再重新启动。旧记录仍留在备份文件夹，初始方案不受影响。请保留整个 `final` 目录，单独复制 HTML 文件无法运行调度功能。

## 开发验证与打包

```powershell
python -m unittest discover -s tests -q
python scripts/check_final_release.py
python scripts/build_final_release.py
```

交付检查会在新的中文与空格路径中启动随包 Python，核对页面资源、接口、演示批次与导出，并检查受保护文件不会通过网页下载。打包脚本生成 ZIP 和 SHA-256 校验文件；演示中的新增记录、密钥、缓存和开发输出不会放入压缩包。
