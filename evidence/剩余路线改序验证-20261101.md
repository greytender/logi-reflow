# 同车剩余路线改序验证 · 2026-11-01

本轮补充人工/模拟回执后的同车剩余配送改序候选、独立核验和人工采用。所有案例都是构造数据，不代表真实履约、企业收益、真实派单或3D装卸可行。

## 操作与约束

1. 保存至少一条回执，在已确认方案的“执行记录与剩余预测”计算候选。尚未签收的货物仍属于原车辆，已收包装随原车保留，不调用全量出仓求解器。
2. 已开始车辆从最后一条门店记录的位置/完成时间继续；尚未开始的车辆从仓库/原班次开始。已回仓车辆不参与改序。
3. 每车剩余6店以内枚举，更多门店最多6轮两店交换。先比较风险条数，再比较剩余道路里程与预计回仓时间；无改进保留原序。风险排序不等于可行性证明，采用前须独立核验全部车辆。
4. 独立核验不调用 `execution.view` 或包装计算助手：重算同车门店完整唯一归属、已收包装、当前与每站先卸后收容量、车辆准入、有向道路时间、门店截止及收班回仓。当前已经超载不能通过改序采用。
5. 候选生成不改变下一店。人工核对并采用后才更新剩余路线；原方案和全部回执不改写。候选绑定输入、原方案、全部回执、当前剩余顺序及已采用剩余版本；新回执/另一版本采用使旧候选失效，旧页按修订号返回冲突。
6. 剩余预测CSV导出当前已采用顺序及风险；原配送CSV继续保留出发前安排和费用。执行回执新增剩余版本编号，旧回执兼容空值。JSON保留候选历史、核验及采用时间。

## 构造回收偏差反例

可复用输入位于 `examples/remaining-pickup/scenario.json`。该文件由三店样例构造，改变回收预测及有向道路估算，不是业务附件或真实路网。

原已确认路线：STORE_002 → STORE_003 → STORE_001。STORE_002于10:00签收后，录入400只压平纸箱，当前车载为314kg/2.784m³，低于350kg/3.5m³上限。但原顺序下一站STORE_003预计收箱后364kg超重。

候选改为STORE_001 → STORE_003：先卸掉84kg货物，离店230kg，最后回收后280kg；通过逐站容量核验。已签收STORE_002与400只已收纸箱均保留。剩余道路里程10km → 27km，两种顺序预计均10:46回仓（道路时间与距离为独立构造输入）。这是容量可行性有代价的反例，不能计算为节费；系统没有重新结算运费。

## 未覆盖

本版不换车、不补车、不转运、不支持当前超载后的卸载/暂存处置、不修改剩余回收预测或业务规则；没有任意在途位置、额外等待事件、GPS/TMS或司机回执。完成时间是人工/模拟输入，数量来源不等于实测箱规。候选只核验重量体积和时间，不核验原箱体坐标、可卸性、冷链或现实道路。费用、实际收益与现场执行仍未验证。

下一步优先补充“当前时刻/位置与等待事件”合同，避免把最后一条记录时间当作一直有效的当前状态。更正回执、部分签收及当前超载处置也需追加事实合同，不能直接编辑旧回执绕过。
