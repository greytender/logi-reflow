# 核心系统审查（2026-11-04）

范围：本机 HTTP 访问边界、密钥隔离、任务持久化、候选版本、人工确认、执行事实、剩余路线与有限三维装卸。页面视觉与算法适配实验另行验收。本报告不代表企业系统或真实履约验证。

## 已修复

**P1：旧版任务读取缺少本机来源校验。** `server.py` 的旧 `/api/session`、`/api/sessions`、`/api/dispatch`、历史及交接读取分支未调用 `check_local`。服务虽监听 127.0.0.1，DNS rebinding 请求仍可携带恶意域名 Host 访问这些数据。新版多仓、原始资料和应用接口已有校验，旧入口遗漏。

修复为在 `do_GET` 分发前统一验证 Host、Origin 和 Sec-Fetch-Site，无效请求返回 403，尚未触碰任务存储。回归覆盖八条旧读取路径，分别使用恶意 Host、外域 Origin 和 cross-site 标记，共 24 次拒绝检查。正常首页、工作台和多仓接口仍可访问。

## 复核结果

- 多仓写入使用数据库修订号的条件更新；并发旧状态不能覆盖新版本。
- 多仓确认再次核验当前输入指纹及最新候选，并拒绝未安排任务；没有自动向企业派单。
- 签收和观察发生后，原输入、重新分车和原方案切换受到事实锁约束。剩余候选指纹纳入回执、观察和已采用顺序，旧候选不能覆盖新事实。
- 回收超容保留已发生记录并标记风险；剩余方案仍经独立容量与时间复核。
- 有箱规的在途改序沿用原箱体坐标核验，不自动重摆车内货物。回收包装仍只有重量与总体积检查，不能当作实际回收摆位证明。
- 密钥使用请求上下文隔离，客户端 cookie 为不透明令牌；导出不含密钥。HTTP 测试使用替身，不重新调用真实付费 API。
